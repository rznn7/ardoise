# Payments Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The group page with its payment feed, the add / edit / delete payment flow, and payment details. The app opens on the last group used.

**Architecture:**
- The pure split computation moves from the backend's payment domain into `@ardoise/shared` (a shared kernel), so the form previews exactly the cents the server stores.
- The backend gains list, update and delete for payments, plus a `name` on group members.
- The frontend gets a root `PaymentStore` that holds each group's feed and applies optimistic create / update / delete. A root `PaymentDraft` holds the add/edit form across its routed steps, so every step is a real history entry.

**Tech Stack:**
- Backend: NestJS 12, Drizzle, Zod contracts, Vitest + testcontainers + supertest.
- Frontend: Angular 22 signals, spartan helm (`native-select`, `toggle-group`, `sheet`, `sonner`, `skeleton`, `input`, `field`), Vitest + Testing Library.
- E2E: Playwright scenarios and the screenshot matrix in `apps/e2e`.

**Spec:** `docs/superpowers/specs/2026-10-26-payments-design.md`

## Global Constraints

- Branch `feat/payments` off `main`. Single-line commit messages, no body or trailers. No code comments.
- Money is integer cents everywhere. Shares always sum to `fullAmount`; the only rounding is `apportion`.
- Any member of the group may edit or delete any payment. Non-member → 403 (`NotAMember`), unknown payment → 404.
- Tap targets: selects, segmented control, number fields and stepper buttons are 44px (`h-11`); member rows and the Save button are 48px (`h-12`).
- Split always opens on **Equally, everyone ticked**. Shares default to 1, % and Exact start empty (0).
- Default title is `Payment, <d MMM>`, e.g. `Payment, 26 Oct` (`Intl.DateTimeFormat('en-GB', { day: 'numeric', month: 'short' })`). It is the title field's placeholder; the label below the field is `Title`.
- `paidAt`: today → the current instant; any other date → 12:00 local time on that date; on edit, an unchanged date keeps the stored `paidAt`.
- Edit / Delete buttons are text only. ‹, +, ⋯, ✕ are icons with an `aria-label`.
- Feature templates follow `docs/design.md` template rules: layout/spacing Tailwind only, text directives for type, no arbitrary values, no component CSS, no inline styles. New building blocks go in `src/app/shared/ui/`.
- Last group: `localStorage['ardoise.lastGroup']`, read/write inside try/catch. Redirect from home at most once per app launch.
- Before calling any task done: `pnpm typecheck` passes (vitest and eslint don't typecheck), plus the touched package's `test` and `lint`.

## Review Focus

1. **Comma decimals and junk in money fields** (`24,5`, `24.50`, `0`, `1.234`, `abc`, `,5`): parse to cents or reject, never a float. Pinned in Task 7 (`parseAmount` specs).
2. **Equal split with every member unticked, shares all 0, % at 99.99, exact off by 1 cent**: Save disabled, nothing sent. Pinned in Task 7 (`PaymentDraft` validity specs).
3. **Back from home after the launch redirect**: lands on home and stays (no bounce back into the group). Pinned in Task 8 (`LastGroup` spec) and Task 12 (scenario).
4. **Reload in the middle of the add flow** (`/payments/new/options` with no draft): it goes to the amount step, not a broken form. Pinned in Task 9 (step guard spec).
5. **Optimistic action refused by the server** (create 400, delete 403): the feed rolls back and a toast explains. Pinned in Task 6 (`PaymentStore` specs).
