# PWA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ardoise installs on the iPhone Home Screen as a standalone app with its own icon, never opens the Safari sheet when navigating, and reloads itself onto a new deploy.

**Architecture:** Static PWA plumbing in `apps/frontend/public` and `index.html` (manifest, iOS meta tags, generated icons), a Caddy header so `index.html` always revalidates, and one frontend service, `VersionWatcher`, that compares `/version.json` across foreground returns and reloads on chunk-load failures. No service worker. Nothing touches the backend: this is frontend infrastructure, so there is no domain or use case involved.

**Tech Stack:** Angular 22 (standalone, `provideAppInitializer`, Router events), vitest + TestBed, `@napi-rs/canvas` + `tsx` (existing backdrop generator), Caddy 2, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-26-pwa-design.md`

## Global Constraints

- Manifest: `name` and `short_name` `Ardoise`, `id: "/"`, `start_url: "/"`, `scope: "/"`, `display: "standalone"`, `background_color` and `theme_color` `#ffffff`.
- Icon artwork: backdrop **violet, sunrise, seed 1**, rendered at the generator's 860×1864 with its usual rng seed (`hashString('violet-sunrise-1')`), cropped to the square at 30 % of the vertical slack; the word `ardoise`, lowercase, white, Figtree Variable weight 500, centred on its ink bounds, wider dimension = 80 % of the side; dark radial halo `rgba(0,0,0,.38)` at 0, `.12` at 55 %, transparent at 80 % of a radius of `side × √2 / 2`. No rounded corners, opaque.
- Maskable variant: same artwork, text wider dimension = 56 % of the side (22 % margin).
- No service worker, no offline, no update banner, no launch images.
- Commit messages: one line, conventional prefix, no body. No code comments.
- Feature-template UI rules from `CLAUDE.md` apply, though this plan adds no template.
- `noUncheckedIndexedAccess` is on. Run `pnpm typecheck` before calling a task done: vitest and eslint do not type-check.

## Review Focus

1. **`/version.json` under `pnpm dev` and in Playwright** is answered by the SPA fallback with `index.html`, not JSON. Expected: no reload, no console error loop. Pinned by `ignores a response that is not version JSON` in Task 3.
2. **The app launches offline or the first fetch fails**, then comes back online on a foreground return. Expected: the later sha becomes the baseline, no reload. Pinned by `adopts the first sha it manages to read as the baseline` in Task 3.
3. **A deploy that is genuinely broken** (chunk keeps 404ing). Expected: one reload, then the error surfaces normally, no reload loop. Pinned by `reloads only once for repeated chunk failures` in Task 3.
4. **A deep link like `/group/3` loaded from the Home Screen or refreshed** goes through Caddy's `try_files` fallback. Expected: it carries `Cache-Control: no-cache` like `/`. Pinned by the curl check in Task 2.
5. **Icon URLs resolve relative to the manifest**, not the page. Expected: absolute `/icons/...` paths that answer 200 with `image/png`. Pinned by the Playwright scenario in Task 2.

test('the app can be installed full screen with its icon', async ({ page }) => {
  await page.goto('/');
  const manifestHref = await page.locator('link[rel="manifest"]').getAttribute('href');
  const manifestResponse = await page.request.get(new URL(manifestHref!, page.url()).href);
  expect(manifestResponse.ok()).toBe(true);
  const manifest = await manifestResponse.json();
  expect(manifest).toMatchObject({ name: 'Ardoise', short_name: 'Ardoise', id: '/', start_url: '/', scope: '/', display: 'standalone' });
  expect(manifest.icons.map((icon) => `${icon.sizes} ${icon.purpose}`)).toEqual(['192x192 any', '512x512 any', '512x512 maskable']);

  const appleIcon = await page.locator('link[rel="apple-touch-icon"]').getAttribute('href');
  for (const src of [...manifest.icons.map((icon) => icon.src), appleIcon]) {
    const response = await page.request.get(new URL(src, page.url()).href);
    expect(response.ok()).toBe(true);
    expect(response.headers()['content-type']).toContain('image/png');
  }

  await expect(page.locator('meta[name="apple-mobile-web-app-capable"]')).toHaveAttribute('content', 'yes');
  await expect(page.locator('meta[name="apple-mobile-web-app-status-bar-style"]')).toHaveAttribute('content', 'black-translucent');
});

### Task 3: Reload onto new deploys

Why a service in `src/app/shared/version/`: it is frontend infrastructure started once at boot, like `ThemeService`. It has no screen, no domain rule, and the backend is not involved: `/version.json` is a static file written into the web image.

**Files:**
- Create: `apps/frontend/src/app/shared/version/version-watcher.ts`
- Create: `apps/frontend/src/app/shared/version/version-watcher.spec.ts`
- Modify: `apps/frontend/src/app/app.config.ts`

**Interfaces:**
- Produces: `export const PAGE_RELOAD = new InjectionToken<() => void>(…)` with a `providedIn: 'root'` factory that calls `inject(DOCUMENT).location.reload()`.
- Produces: `@Injectable({ providedIn: 'root' }) export class VersionWatcher` with `start(): void`. Constants `VERSION_URL = '/version.json'`, `CHUNK_RELOAD_KEY = 'ardoise.chunk-reload'`.

Behaviour, fixed by the tests below:
- `start()` fetches `VERSION_URL` with `{ cache: 'no-store' }` and keeps the `sha` as baseline. On `visibilitychange` with `document.visibilityState === 'visible'`, fetches again; if a baseline exists and the new sha differs, calls `PAGE_RELOAD`. If no baseline yet, the new sha becomes it.
- A response counts only if it is OK and parses as an object with a string `sha` that is not `'dev'`. Anything else (network error, non-OK, HTML, bad JSON, `dev`) is ignored silently.
- Router `NavigationError` whose error message matches `/dynamically imported module|Importing a module script failed|Failed to fetch dynamically/`: if `sessionStorage[CHUNK_RELOAD_KEY]` is unset, set it to `'1'` and call `PAGE_RELOAD`; if set, do nothing. Every `NavigationEnd` removes the key. Wrap `sessionStorage` access in try/catch.

- [ ] **Step 1: Write the failing tests**

Setup: `vi.stubGlobal('fetch', fetchMock)` where `fetchMock` returns queued `Response` objects (`new Response(JSON.stringify({ sha: 'aaa', date: '' }))`); provide `{ provide: PAGE_RELOAD, useValue: reload }` with `reload = vi.fn()`; flip visibility with `Object.defineProperty(document, 'visibilityState', { value: 'visible', configurable: true })` then `document.dispatchEvent(new Event('visibilitychange'))`; `await vi.waitFor(...)` or flush promises between steps. For router cases, provide `provideRouter([])` and emit through `TestBed.inject(Router)`'s events by navigating to a route whose `loadComponent` rejects with `new TypeError('Failed to fetch dynamically imported module: /chunk-ABC.js')`. Clear `sessionStorage` in `beforeEach`.

Tests in `describe('VersionWatcher')`:
- `reloads when the app comes back with a new sha`: responses `aaa` then `bbb` → `reload` called once.
- `stays put when the sha is unchanged`: `aaa`, `aaa` → not called.
- `does not check when the app goes to the background`: visibility `hidden` + event → `fetch` called once (startup only).
- `ignores a response that is not version JSON`: startup `aaa`, then `new Response('<!doctype html>…', { headers: { 'content-type': 'text/html' } })` → not called; then a third return with `aaa` → still not called.
- `ignores the dev sha`: `dev` then `bbb` → not called (the `bbb` becomes the baseline).
- `adopts the first sha it manages to read as the baseline`: startup `fetch` rejects, then `aaa`, then `bbb` → called exactly once, on the third.
- `reloads once when a lazy route fails to load`: failing navigation → `reload` called once and `sessionStorage.getItem('ardoise.chunk-reload')` is `'1'`.
- `reloads only once for repeated chunk failures`: two failing navigations → `reload` called once.
- `clears the chunk guard after a successful navigation`: key preset to `'1'`, navigate to a route that loads → key is `null`.
- `ignores navigation errors that are not chunk failures`: route guard throwing `new Error('boom')` → not called.
